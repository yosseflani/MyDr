# מדיניות תוכן העזרה הראשונה ב־MyDr

> **מסמך זה מתאר מדיניות מוצעת בלבד. הוא אינו אישור רפואי, אינו מכיל הנחיות רפואיות, ואינו מחליף את שיקול דעתם של אנשי מקצוע מוסמכים.**

## 1. מקורות מוסמכים בלבד

- כל הנחיה רפואית באפליקציה חייבת להתבסס על מקור רפואי מוסמך ומזוהה, כמו ארגון רפואה דחופה לאומי, משרד הבריאות או הנחיות מקצועיות מוכרות.
- לכל נושא נרשמים המפרסם, שם המסמך וקישור HTTPS למקור (`source` בקובץ התוכן).
- אין לנסח הנחיות מהזיכרון, מאתרים לא מוסמכים או באמצעות AI. אין ליצור הוראות חירום באופן אוטומטי.
- יש לוודא שיש זכות להשתמש בתוכן. ייתכן שתוכן של גופים מוסמכים מוגן בזכויות יוצרים.

## 2. אימות מקצועי לפני פרסום

- הנחיה רפואית מתפרסמת רק אחרי שאיש מקצוע מוסמך השווה אותה מילה במילה למקור ואישר אותה.
- פרטי האימות (`verification`) כוללים את תאריך האימות ואת תפקידו או תוארו המקצועי של המאמת. לא נכללים בהם פרטים אישיים מעבר לנדרש.

## 3. בדיקה טכנית לעומת אישור רפואי

אלה שני שלבים נפרדים, ואף אחד מהם אינו מחליף את השני.

| | בדיקת תקינות טכנית | אישור רפואי |
|---|---|---|
| מי מבצע | הקוד (`FirstAidContentParser`) והבדיקות האוטומטיות | איש מקצוע רפואי מוסמך |
| מה נבדק | מבנה הקובץ, גרסת ה־Schema, שדות חובה, מזהים כפולים, קישור HTTPS, תאריכים, ושנושא בהכנה לא מכיל הוראות | נכונות, שלמות ובטיחות ההנחיות מול המקור |
| מה זה מבטיח | שהאפליקציה לא תציג תוכן פגום או חלקי | שהתוכן נכון רפואית |

- סימון `"status": "verified"` בקובץ התוכן **אינו** מספיק כדי שתוכן יוצג כמאומת.
- נושא נחשב מאומת רק אם יש לו אישור מתאים ברשימת האישורים שבקוד (`FirstAidApprovals.trusted`), שעוברת Code Review.
- האישור כולל טביעת אצבע (SHA-256) של התוכן המדויק שאושר. כל שינוי בתוכן, אפילו של תו אחד, מבטל את האישור, והנושא חוזר אוטומטית למצב "בהכנה".

## 4. נושאים בהכנה (pending)

- כל נושא נשאר במצב `pending` עד להשלמת האישור הרפואי.
- נושא בהכנה מוצג עם כותרת ותיאור קצר בלבד, ובלי שלבים, אזהרות או הפניות. האפליקציה אוכפת זאת ברמת הקוד.
- כפתורי החיוג למוקדי החירום זמינים תמיד, בלי קשר למצב התוכן.

## 5. תהליך מוצע לעדכון תוכן

1. **הכנה:** כותב התוכן מעדכן את הנושא ב־`assets/first_aid/he.json` על פי המקור, מעלה את `contentVersion` ומעדכן את `publishedAt`.
2. **בדיקה טכנית:** מריצים את הבדיקות האוטומטיות. כל עוד אין אישור, הנושא יוצג כבהכנה, והקוד ידווח על טביעת האצבע שממתינה לאישור (`unapprovedFingerprints`).
3. **אישור רפואי:** איש מקצוע מוסמך בודק את התוכן המדויק מול המקור.
4. **רישום האישור:** אחרי האישור מוסיפים את טביעת האצבע לרשימת האישורים בקוד, ושני אנשים נוספים לפחות עוברים על השינוי ב־Code Review.
5. **בדיקה חוזרת:** מגדירים מועד קבוע לבדיקה מחדש, למשל פעם בשנה, וגם בכל פעם שהמקור מתעדכן. תוכן שהמקור שלו השתנה חוזר לשלב 1.

## 6. אחריות

- המסמך מתאר את התהליך הטכני והארגוני המוצע.
- ההחלטה אילו מקורות לאמץ, מי מוסמך לאשר, ומהי תדירות הבדיקה החוזרת היא של בעלי המוצר ואנשי המקצוע הרפואיים, ולא של המפתחים.
